## 每阶段的执行规则

1. 开始时将状态更新为 in_progress，记录源码提交、输入数据、预算与已知缺失项；只有 S0 可立即启动。
2. 证据写入本阶段独立目录，状态引用实际产物。支持 planned、in_progress、passed、failed、blocked、skipped；skipped 必须有理由，不能等同通过。
3. 科学负结果、工程故障和资源阻碍分开记录。延期只调整日程，不伪造验收，也不因临近汇报放松安全合同。
4. 模型训练仅在指定服务器执行。当前连接状态须重新检查；旧 GPU 空闲情况不视为实时证据。
5. 新增训练建议上限三组×三seed×10000接受决策，另计最多1000决策试跑；S3开始前确认实际组别、同预算比较方式及墙钟上限。
6. 完成阶段后先下载模型、日志和配置，再做GitHub归档及下载核验。原J-02 Release、旧Test和阈值不覆盖。

## 范围与降级

P0：S0/S1基础可用、安全与文档；P1：S2/S3延迟与必要训练；P2：S4已有世界模型接入展示。新JEPA机制、长想象轨迹、完整五seed策略研究放到中旬交付之后。

若会议五类型版本未找到，用已核验版本准备基础交付并明确差异；若优化或新模型失败，保留已验证基线及失败证据；不得把失败J-02候选直接接入来凑展示。群发材料须另获明确发送授权。
