# 汇报问答底稿

## 为什么不继续训练？

S3 的判断是当前交付不需要新增训练：S1-R2 的因果/确认合同已通过，S2 的优化是推理入口变化且 checkpoint 未变，S4 只读/回退边界已通过。剩余阻塞项是五类型资产、控制周期、GPPO-History 和公平对照；在这些输入未冻结前训练只会制造不可比权重。若评审明确要研究公平增益，下一轮再按固定预算训练。

## 五类型在哪里？

当前可验证代码只有 UAV、Region、Target 三种节点；4/4/3 是实体数，不是类型数。Task 是 UAV 的状态字段，Event 是事件记录。五类型需要定义节点生命周期、特征、边、mask 和 checkpoint 兼容规则，目前不能通过改名宣称存在。

## 能量规划是策略学出来的吗？

不是本次证据支持的结论。当前 energy-insufficient 主要验证执行层拒绝、NOOP/回退和安全计数；S1-R2 的能量字段/探针属于安全链合同。没有完成“带能量输入的独立策略训练 + held-out 对照”，所以不能说策略自主学会了能量规划。

## 世界模型改善了 return 吗？

没有可声明的稳定改善。A 的 Shadow 被设计成 side-car，OFF/ON 60/60 等价、回报差为 0；B 是历史 EAWM-GPPO 的上下文消费复现，不是 S3 pure GPPO 的公平对照。T-05 正式结果也保留了未建立稳定策略增益的负结论。

## CPU 比 GPU 快，是算法结论吗？

只是在这台 2×RTX 2080 Ti、这个小图规模和测量协议下，CPU 端到端均值低于 `cuda:0`。这可能来自小负载、搬运和同步，不能外推成算法层优劣或所有硬件结论。

## “三重原子攻击”现在是什么意思？

弃用该名称。规范名称是“三因素复合扰动压力测试”：单机损毁、通信异常、低置信度观察，按固定发生/到达顺序和证据源复现。它不是一个现成攻击类，也不是安全认证名称。

## 离部署还有多远？

当前达到的是工程候选交付：可复现三类型 GPPO、只读 Shadow、fail-closed 回退和历史 adapter 入口。距离部署还缺真实系统接口认证、明确控制周期与规模、五类型/任务合同、真实 OOD/延迟压力、故障恢复测试和公平多 seed 增益证据；本次不做实时或飞控认证声明。
