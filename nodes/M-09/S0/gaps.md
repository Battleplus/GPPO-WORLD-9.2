# S0 缺失项、影响和处理决定

| 缺失/不确定项 | 证据与影响 | 处理决定 | S1 启动影响 |
|---|---|---|---|
| 会议五节点类型源码、模型、数据 | 现有实现只有 UAV/Region/Target；Task/Event 是字段/记录 | 按三类型冻结演示；取得具体提交前不宣称五类型 | 不阻塞三类型 S1；阻塞五类型验收和比较 |
| GPO 的实际实现定义 | 仓库没有独立 GPO 标识 | 保留“会议所称 GPO”待来源，不等同 GPPO | 阻塞 GPO/PPO 性能结论 |
| 通用紧急 Task 与 deadline | 只有 Target discovered/Region vacancy 等事件，没有独立任务队列和期限 | S1 实现可控紧急任务或明确降级 | 阻塞该场景通过 |
| 能量状态和约束 | UAV、图特征、mask、结束条件均无 battery/energy | S1 实现并判断 checkpoint 兼容性；不能伪造既有支持 | 阻塞能量不足场景通过 |
| 返航、换电/充电 | 动作空间只有 UAV–Region 与 NOOP | 作为显式产品缺口；如要求展示必须新增动作/规则 | 阻塞相应能力声明 |
| 完整通信中断场景 | 有 detector partition/loss/order 和执行安全链，无已冻结 S1 场景及轨迹 | 固定持续时间、恢复和证据可见时刻后验收 | 不阻塞编码启动，阻塞 S1 通过 |
| 三因素可控组合 | 单机损毁可用，通信与 0.55 confidence 有底层构件，缺统一注入配置/测试 | 按定义文档实现并保存完整 tape | 阻塞复合场景通过 |
| “慢 3～4 倍”原始依据 | 未找到同硬件/模型/口径原始数据 | 降为待复现会议观察；S2 重新测 | 不阻塞 S1 |
| 服务器实时状态 | 2026-09-06 已成功只读登录；两张 RTX 2080 Ti 在检查时均无计算占用，`dporl` 与用户提供版本一致 | 每次正式训练前仍须重新检查；本次空闲结果不是资源预留 | 当前不阻塞启动；训练前须再做瞬时复查 |
| 汇报日期、控制周期和真实规模 | 规划仍是暂定日期；无竞赛时限/规模 | 保持 open input；S2 不自定实时阈值 | 不阻塞 S1 功能启动 |

S0 本身不因五类型和服务器缺失而 blocked，因为阶段退出条件允许“差异和缺失项有处理决定”，且三类型基础模型已锁定并核验。S1 状态仍为 planned：可以开始实现，但目前不具备直接宣告 S1 passed 的条件。
