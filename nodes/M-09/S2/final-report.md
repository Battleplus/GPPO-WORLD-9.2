# S2 最终报告

## 结论

S2 `passed`。服务器正式测量使用三类型 GPPO-Adaptive、seed1101/50000 checkpoint、6 类×10 条固定 tape、CPU 与 `cuda:0` 分设备、baseline/优化交错各 5 遍。没有训练，没有进入 S3。

CPU 端到端决策墙钟均值为 `4.277103 ms`，P50/P95/P99/最大值为 `3.529765/6.493045/6.571683/6.891225 ms`；优化后为 `4.150364 ms`，P50/P95/P99/最大值为 `3.433833/6.299090/6.400226/6.668761 ms`。GPU 端到端为 `5.673699 ms`、P50/P95/P99/最大值 `4.644806/8.732964/8.765926/8.995606 ms`；优化后为 `5.489172 ms`、`4.502288/8.412065/8.449788/8.533808 ms`。

纯策略前向是最大耗时段：CPU baseline `2.197379 ms`（约端到端 51.4%），GPU baseline `3.075608 ms`（约 54.2%）。graph 构建约 `0.25 ms`，submit/执行约 `0.81 ms`。冷启动模型加载约 CPU `10.99 ms`、GPU `153.94 ms`。

## 优化与边界

只采用 `torch.inference_mode()` 这一项低风险优化；CPU tape 成组端到端改善 `2.927%`，GPU `3.290%`，配对区间均不跨 0。优化前后 60/60 行为、安全、确认和结束分类一致。没有实施第二项优化，也没有验证“五类型比 PPO 慢 3～4 倍”：缺少同条件普通 PPO、两类型和五类型模型及数据资产。

## 下一阶段

S2 已满足结束条件，S3 仍保持 planned，未自动启动。若后续训练，首要问题应是补齐公平的普通 PPO/五类型对照资产，并验证规模扩展和真实控制周期；本阶段不自造实时阈值。
