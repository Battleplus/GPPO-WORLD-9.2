## 1. 成本比较勘误

完整决策链均值必须注明比较对象：

| 比较 | 完整链路均值 | 差异 |
|---|---:|---:|
| C 对 B | 2.1217 ms vs 2.3177 ms | C 低约 8.5% |
| C 对 A | 2.1217 ms vs 1.8967 ms | C 高约 11.9% |

actor 调用总数为 A=814、B=818、C=504；因此 C 相对 A 下降约 38.1%，相对 B 下降约 38.4%。这些是调用数比较，不是完整计算成本比较。

C 的任务完成数仍为 49/288，低于 A=84/288 和 B=82/288；通信代理字节量 C=17,855,743，也未低于 A=17,660,903 或 B=17,781,076。因此没有“保持任务效果并降低成本”的证据。CPU、2线程、无预热、不含落盘的延迟只适用于本次仿真测量，不推断 GPU 表现、稳定加速或竞赛实时性。

## 2. 恢复账本口径勘误

旧的 144/144/144 是每变体全部场景事件数：每个变体 48 个 tape，每个 tape 3 个事件（48 disconnect、48 reconnect、48 damage）。它不是“确有任务中断”的分母。

按已有 `event_ledger` 的 `affected_task_ids` 复算，任务中断事件分母为：

| 变体 | 全部场景事件 | 有受影响任务的事件 | disconnect | reconnect | damage |
|---|---:|---:|---:|---:|---:|
| A | 144 | 12 | 7 | 0 | 5 |
| B | 144 | 12 | 7 | 0 | 5 |
| C | 144 | 7 | 1 | 0 | 6 |

下列指标不是同一递减漏斗，分别报告：

| 指标 | A | B | C | 口径 |
|---|---:|---:|---:|---|
| 合法获知 | 12/12 | 12/12 | 7/7 | 事件数；`received_at` 非空且晚于事件时间 |
| 公开候选 | 7/12 | 6/12 | 2/7 | 事件数；受影响任务候选且 `time_start >= legally_known_at` |
| 接管接受（更正） | 3 个事件、3 条命令 | 1 个事件、2 条命令 | 0 个事件、0 条命令 | 受影响任务；接受时间不早于合法获知 |
| 服务恢复（有效替代服务） | 0 | 0 | 0 | 事件数；记录到受影响任务的 service，且资源未被原资源排除 |

旧值“接管接受 A/B/C=12/12/7”保留为历史值，但不再作为合法接管结果使用。原因是原测量代码只按“accepted 且 task_id 属于 affected_task_ids”计数，没有要求 accepted 发生在 `legally_known_at` 之后；完整 step ledger 复算显示旧计数包含事件前接受。它还隐含允许一个事件多条命令：旧命令数为 A/B/C=15/15/7；更正后命令数为 3/2/0。B 的更正结果中，一个事件有两条合法获知后的接受命令，因此事件数与命令数不可合并。

服务恢复 0 的准确含义是：在已有 2,458 条 step ledger 中，`new_events` 字段均存在；与受影响任务关联的 service 事件为 A/B/C=15/15/10，但全部来自被排除的原资源，替代资源为 0。因此没有“漏记字段”证据，但这仍只说明本次仿真没有符合定义的有效替代服务恢复，不代表真实网络或历史训练行为。

## 3. 安全声明边界

`no_observed_violation` 仅表示本次确定性 replay 的已记录范围内没有候选违规。记录覆盖 command、ACK、lease、fencing 字段，并检查重复 command ID 和不完整 active-lease 记录；正常 stale、过期、masked 或资源不足拒绝不计为安全违规。

它不替代原训练 raw ledger、完整逐事件安全审计、真实网络流量或生产保证。原训练 raw ledger 缺失是历史限制，不通过重新训练解决；字节量仍是 compact-JSON 序列化代理，不是真实网络流量。

## 4. 结果与资产关系

任务结果不变：A=84/288、B=82/288、C=49/288；已有 replay 与正式参考字段仍为 144/144 episode 匹配。本勘误新增资产，不覆盖原报告、原始结果或旧哈希。最终限定结论是：B 未建立改善证据；C 相对 B 的本次 CPU 完整链路均值较低，但任务效果明显下降；同硬件 GPU 测量和原服务器进程状态仍未知。
