# 弱通信场景与其他实验设置说明

更新：2026-09-10。本文解释授权恢复修复后正式A/B/C训练及CPU复评使用的冻结场景，不改变实验参数。数值直接提取自已核验SHA-256的迁移包，详细原值见[机器可读配置](12-weak-communication-frozen-settings-20260910.json)。

## 一句话理解实验

4架无人机执行陆续到达的6个任务。控制端收到的位置、电量、任务状态可能滞后、丢失或失效，部分任务指令和ACK可能丢失；场景同时包含UAV断联、恢复和损毁。算法需要在合法信息、执行合同和deadline约束下分配任务。

这是程序内消息与任务执行仿真，不是真实无人机无线网络或飞控实验。下文时间、距离、能量都是仿真单位，不能直接解释为真实链路秒数、米、电池容量或竞赛要求。

## 1. 最新正式训练的弱通信参数

最新正式配置使用`composite`，多种通信问题同时出现。

| 项目 | 冻结设置 | 含义 |
|---|---|---|
| 遥测延迟 | 固定0.5，加0～0.75随机延迟 | 到达时已不是即时状态；延迟变化可使部分消息乱序 |
| 遥测随机丢失 | 15% | 对模拟遥测消息的丢弃概率，不是实网测量丢包率 |
| 连续遥测中断 | `[3,5)`、`[10,12)` | 这些时间段生成的遥测被丢弃；已排队消息是否送达仍由队列决定 |
| 新分配命令丢失 | 5% | 丢失命令不进入任务分配bridge |
| ACK丢失 | 10% | 控制端收不到确认；不撤销执行端已经接受的命令 |
| 遥测最大有效年龄 | 2.5 | 过期字段不能继续当作新鲜有效信息形成对应候选 |
| 遥测重复投递概率 | 0 | 代码支持重复投递，本轮正式profile没有开启 |
| 续租额外延迟、乱序窗口、重复概率 | 均为0 | 续租支持这些机制，但本轮profile未打开；续租请求使用5%的丢失预算 |
| 自动重传 | 无自动重传机制 | 定期续租不等于自动重发丢失的新分配命令 |

遥测、命令、ACK是三条独立逻辑链路。各消息的随机命运按seed、链路和消息身份确定，重复运行可重现；不同策略动作产生不同消息，不能声称所有分支逐条消息内容相同。

**遥测中断与UAV断联是两种机制。** 遥测中断主要影响控制端的信息可见性，不直接把所有无人机停机；UAV的disconnect事件则按当前ServiceClock合同中断该机执行。策略必须等合法消息送达才能获知相关状态，不能直接读取预先冻结的未来故障表。

新分配命令和ACK在当前默认配置主要模拟丢失，成功路径在step内处理，`ack_latency=0`。不能把本配置描述成已经完整模拟了三条链路的独立异步延迟、真实带宽拥塞或无线信道。

## 2. 代码提供的通信对照级别

| profile | 链路扰动设置 |
|---|---|
| ideal | 不额外施加消息链路扰动 |
| telemetry-delay | 遥测额外延迟0.5 |
| random-loss | 遥测丢失概率20% |
| burst-loss | 遥测中断`[3,5)`、`[10,12)` |
| reorder | 遥测附加延迟窗口0～0.75 |
| recovery | 遥测中断`[3,6)`，之后按正常消息规则继续 |
| composite | 前表所列正式复合参数 |

这些是可选择的profile，不表示最新12,288步正式训练逐级跑过全部profile。最新正式矩阵固定使用composite；历史课程实验另有独立版本。profile只控制消息链路，`ideal`不自动删除任务场景中的UAV损毁或断联事件。

## 3. 无人机、图和动作

| 项目 | 冻结设置 |
|---|---|
| UAV | 4架，初始位置均为`(0,0)` |
| Task | 6个任务槽，本批场景每episode共6个任务，陆续到达 |
| Region / Target | 3个Region、4个Target |
| Event容量 | 4个槽；五类型是实体类型数，不是总节点数 |
| 图类型 | UAV、Task、Region、Target、Event |
| episode时限 | 18个仿真时间单位，满足终止条件时可提前结束 |
| 决策间隔 | 1个仿真时间单位 |
| 动作 | 24个UAV–Task候选组合＋NOOP，共25个 |
| 每周期新分配 | 最多一个新分配；候选须通过mask与执行检查 |
| 持续执行 | 已接受任务可并行移动、服务、续租 |

NOOP只表示不新增分配，不等于清空已有任务或让所有UAV停工。任务分配不等于完成：无人机须移动到任务位置，累计所需服务量，并在deadline内完成。这里是M-10 UAV–Task新合同，不能与T-05/M-09的旧17动作UAV–Region合同混用。

## 4. 一个实际冻结测试场景

场景ID：`test-mixed-seed-2107101`，seed `2107101`。以下展示到小数点后三位；机器可读附件保留完整数值。

| 任务 | 到达时间 | deadline | 所需服务量 | 位置 |
|---|---:|---:|---:|---|
| task-0 | 0.000 | 6.718 | 1.373 | (1.575, 0.543) |
| task-1 | 0.000 | 8.306 | 1.479 | (2.327, 1.801) |
| task-2 | 1.867 | 11.084 | 1.070 | (0.616, 2.686) |
| task-3 | 3.375 | 11.915 | 2.395 | (3.153, 0.050) |
| task-4 | 5.303 | 14.813 | 1.403 | (0.885, 2.773) |
| task-5 | 6.646 | 16.621 | 1.626 | (3.078, 2.749) |

同一场景中，`uav-0`在3.824时断联，6.799时恢复连接，7.288时损毁。它还叠加前表的遥测中断和随机消息丢失。故障可以发生在没有活动任务的UAV上，因此“场景事件数”不等于“真实任务中断机会数”。

例如task-3在3.375到达、11.915截止，需要2.395单位服务。服务速率为1时，单纯服务需要约2.395时间单位；移动、等待、信息获知及执行中断还会占用时间。仅凭任务总窗口不能证明完整调度可行或不可行。

其他tape通过冻结seed改变任务到达、位置、deadline、服务量、priority和故障对象/时刻。任务模板到达时间为0/0/2/3/5/7，deadline为7/8/11/12/15/17；非回归场景在模板上扰动，而不是所有episode都用完全相同的6条任务。

迟到任务与priority提供动态任务情形，但不能把本批任务生成器扩大描述为已覆盖真实竞赛所有紧急任务类别。OOD的`energy_insufficient`场景将服务量乘2.5；它不是单独模拟真实电池故障或换电事件。

## 5. 能量、奖励与执行合同

| 参数 | 数值 |
|---|---:|
| 每架UAV初始能量 | 9.0 |
| 移动速度 | 1.0 |
| 服务速率 | 1.0 |
| 移动单位时间能耗 | 0.35 |
| 服务单位时间能耗 | 1.0 |
| 等待单位时间能耗 | 0.05 |
| command TTL | 0.5 |
| lease TTL | 2.0 |

当前每步奖励为：新增完成任务数×10，减新增过期任务数×4，减能耗×0.08；当反馈满足代码的拒绝惩罚条件时再减0.25。不是对每一条底层ACK或通信账本拒绝都统一扣0.25。

任务有priority字段，配置也保留`reward_priority_scale=2.0`，但冻结源码`_reward_and_counts`没有使用该参数。因此不能声称高优先级任务完成后一定获得更多奖励；本次只说明现状，没有修改奖励。

ACK、版本、lease、fencing和资源门禁继续生效。断联、损毁、能量耗尽或租约失效会影响执行；恢复连接不会自动把中断任务恢复成原分配，仍需满足合法接管/执行条件。返航、换电、充电目前没有作为动作实现，其最低验收范围仍待确认。

## 6. A/B/C与训练评估设置

| 组别 | 配置 |
|---|---|
| A | Graph-5 GPPO，每周期运行actor |
| B | 同样的Graph-5策略，增加冻结世界模型输入，每周期运行actor |
| C | 在B基础上使用事件触发，部分周期跳过actor，维持合法执行 |

正式runner中三组`history=False`；B/C增加世界模型上下文，不等于额外训练了独立GPPO-History对照。三组使用相同任务/通信tape、动作、奖励和环境步预算，世界模型预训练成本单列。

最新正式C阈值为**0.45**，最大重规划间隔参数为**3**。这是validation未找到合格效果/成本方案后保留的负结果配置，不是已证明最优阈值；不要与历史0.1或runner默认值混用。
